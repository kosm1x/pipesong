## 4. Phases

Rule that dissolves "which first?": **every phase is split into "build now on the VPS"
and "gate needs GPU + keys."** Build everything buildable now; run all gates in one GPU
window when §2 is satisfied.

### Phase 2 — Flux / Pipecat 1.x merge

- **State:** blocked on §2. Code complete; nothing left to build.

### Phase A — Pre-recorded audio + TTS mixer

- **What it buys:** removes the TTS leg (~450–800 ms with Kokoro) for phrases in a
  pre-recorded corpus. **Honest accounting on "TTFA ~0 ms":** it only holds for phrases
  that bypass the LLM. Any phrase the LLM decides still pays STT + LLM TTFT (~130 ms at
  20 concurrent) before the mixer can match; the saving is the Kokoro leg.
- **A.0 — Pre-recorded disclosure (standalone, zero-risk):** the recording disclosure
  already goes out as a `TTSSpeakFrame` with no LLM (`src/pipesong/pipeline.py`, text
  in `config.py`). It is the one genuinely ~0 ms case and the most sensitive legally.
  Record one clip per agent × language; serve it as audio directly.
- **A.1 — Build now (no GPU):**
  - `src/pipesong/prerecorded/corpus.py` (load + hash `.wav` clips by intent) and
    `mixer.py` (`PreRecordedMixer`: match normalized LLM output → audio or `None`).
  - Integrate in `pipeline.py` ahead of `KokoroTTSService`.
  - **Unit tests** — the repo's first: exact match, near-miss → `None`, empty corpus,
    `es`/`en`.
  - Prerequisite for generating the corpus on CPU: install `kokoro` (+ system
    `espeak-ng`) into the `.venv`, or run the kokoro-fastapi CPU container. Kokoro-82M
    on CPU is slow but fine for offline batch generation.
  - Starter corpus (generic): greeting, "un momento por favor", "permítame verificar
    esa información", disclosure, appointment-confirmation, "¿podría repetirme su
    nombre?", hand-off to a human. Per-deployment corpora are configured, not coded.
- **A.2 — Gate (GPU + Deepgram key):** TTFA P50 < 200 ms on corpus phrases in a live
  pipeline (STT → LLM → mixer), **and** match precision measured — the wrong clip is
  worse than a slow one.

### Phase B — MCP server

- **What it buys:** an agent (or a developer in an agentic IDE) can create/tune agents
  and place test calls without touching the REST API.
- **B.1 — Build now (no GPU):** `src/pipesong/mcp/{server.py,tools.py}` (FastMCP),
  wrapping endpoints that **already exist**:

  | MCP tool                   | Existing REST                                 |
  | -------------------------- | --------------------------------------------- |
  | `agent_create`             | `POST /agents`                                |
  | `agent_update`             | `PATCH /agents/{id}` (incl. `voice`, `eot_*`) |
  | `agent_list` / `agent_get` | `GET /agents`, `GET /agents/{id}`             |
  | `agent_delete`             | `DELETE /agents/{id}`                         |
  | `call_start`               | `POST /calls/outbound`                        |
  | `call_status`              | `GET /calls/{id}` (+ `/latency`)              |
  - Voice binding lives on the agent record (`agents.voice`), not in a request header.
    The per-client header pattern from VoiceStudio is an HTTP multi-tenant idiom; for an
    MCP the agent is a parameter.
  - `generate_speech` / `transcribe` are out of B.1 — they need Kokoro/Deepgram running.
    Add in B.2 if there is a consumer.
  - Tests: each tool against the API in test mode (SQLite `:memory:`), no telephony.

- **B.2 — Gate (GPU + Deepgram + Telnyx):** an agent creates a PipeSong agent and
  completes a test call end-to-end through the MCP.

### Phase 3 — Inference-stack modernization (post-merge, separate branch)

Largest documented payoff, deliberately decoupled from the Flux merge:

1. vLLM **0.25.1** + `awq_marlin` + `--enable-auto-tool-choice`.
2. Retire the `ToolCallProcessor` regex shim → Pipecat native function calling
   (`FunctionCallUserMuteStrategy` and number conversion move to their proper homes;
   `SpanishOnlyFilter` **stays** — Qwen3.x still code-switches to CJK).
3. Model A/B vs Qwen2.5-7B-AWQ: **Qwen3.5-9B-AWQ** (thinking off) primary,
   **Ministral-3-8B-FP8** fallback. Measure Spanish tool-call accuracy (bar: current
   60%), TTFT at 20 concurrent, CJK-filter fire rate.
4. Re-run the Phase 4a latency suite; update the PLAN.md cost model.

- **State:** after the Phase 2 merge. Needs GPU.

### Phase C — Speech-to-speech

- **State:** last, conditional. Not before Phase 2 + A + B are done.
- **Scope limit:** only for deployments **without strict data-residency requirements**.
  Regulated verticals (e.g. healthcare in Mexico under LFPDPPP / NOM-024-SSA3) stay on
  the self-hosted cascade (Flux + local LLM + Kokoro); cloud S2S (Gemini Flash Live,
  GPT Realtime) is not an option there.
- **Gate:** same script, cascade vs S2S → E2E < 500 ms at equivalent WER, or S2S is dropped.

## 6. Risks and assumptions

- Corpus clips generated with Kokoro use the same voice as live TTS, so there is no
  audible seam. If human-recorded clips are used later, the mixer must handle the
  voice transition.
- Intent-matched playback can pick the wrong phrase; A.2 measures precision, not only
  latency.
- Flux pricing is 1.8× Nova-3; the target (< $0.03/min) still holds, but it needs an
  explicit sign-off, not an assumption.
- With no existing test suite, each phase ships its own tests (A.1, B.1) — no
  exceptions.
