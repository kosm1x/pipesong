## 3. The two code fixes (Phase 0)

**(a) Flux import** — `pipeline.py:20`:

```diff
-from pipecat.services.deepgram.flux import DeepgramFluxSTTService
+from pipecat.services.deepgram.flux.stt import DeepgramFluxSTTService
```

**(b) STTMuteFilter → user-mute strategies** (removed in 1.0.0; replacement lives in
`pipecat.turns.user_mute`): drop `pipeline.py:27` import and the `stt_mute` processor
(`:154-156`, `:162`); configure the aggregator instead:

```python
from pipecat.turns.user_mute import (
    FirstSpeechUserMuteStrategy,      # replaces STTMuteStrategy.FIRST_SPEECH (disclosure)
    FunctionCallUserMuteStrategy,     # replaces STTMuteStrategy.FUNCTION_CALL
)
# on LLMUserAggregatorParams / LLMContextAggregatorPair per 1.7.0 docs — verify exact
# kwarg at install-smoke time (docs.pipecat.ai/server/turns/user-mute)
```

Semantics note: `FunctionCallUserMuteStrategy` keys off Pipecat's _native_ function-call
frames. Our prompt-based `ToolCallProcessor` never emits those — so FUNCTION_CALL muting was
**already dead code** under the old design too. It becomes real only after Phase 3 (native
tool calling). Fine to wire now; it's inert until then.
